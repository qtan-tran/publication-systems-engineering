# Beta Candidate Freeze

Status: **technical beta-candidate staging; not a public licensed beta**.

The current release freezes the public-facing contracts that already exist. It does not authorize publication under a final community license.

## Freeze scope

The following surfaces are frozen for the beta-candidate staging line unless a documented migration is supplied:

- CLI command names and primary exit-code semantics;
- project directory contract generated by `pse new`;
- profile manifest schema 1.1, with legacy 1.0 read compatibility;
- semantic module manifest schema 1.1 / API 1;
- locator scheme schemas 1.0;
- semantic module activation schema 1.1;
- parallel-text schema 1.0;
- bilingual-layout schema 1.0/1.1 compatibility;
- semantic IR schema 1.0;
- QA severity names: `error`, `warning`, `review`, `info`;
- proof/release artifact boundaries and provenance-manifest roles.

Freeze means compatibility is intentional, not that defects can never be fixed. Security and correctness fixes may change behavior when continuing the previous behavior would be unsafe or materially wrong.

## Not frozen

The following remain explicitly pre-beta and may evolve:

- exact visual design of neutral profiles;
- visual-regression tolerances across operating systems;
- enterprise signing/PKI adapters;
- commercial-license pricing and contract terms;
- future semantic families;
- non-PDF output formats.

## Public beta hard gates

A public licensed beta must not be tagged until all of these are true:

1. final community/source-available license reviewed by qualified counsel and committed as `LICENSE`;
2. contributor-rights model for dual licensing finalized;
3. commercial licensing contact channel published;
4. live GitHub CI passes on Windows, macOS, and Linux for the beta-candidate commit;
5. release checklist and checksum manifest pass on the candidate tag.

Until then, repository snapshots are engineering candidates only.
## Exact-commit release evidence

Release-candidate evidence must be tied to a specific Git commit. Run `python scripts/release/candidate_evidence.py` only from a clean, non-shallow checkout. The command records the exact `HEAD`, runs the public-tree integrity gate and full-history high-confidence credential/key scan, and writes machine-readable evidence under `tests/_output/release-evidence/`.

A passing local report is not equivalent to live cross-platform CI and does not record legal approval. Public licensed-beta authorization remains blocked until the external legal and live-CI gates are independently satisfied.
