# Generated Project Contract — current release

Status: **current generator contract**

A project generated by `pse new` is a private downstream publishing project. It is not part of the public PSE framework repository and must not expose unpublished manuscripts by default.

## Canonical project sources

The following are project-owned source-of-truth inputs:

- `book.yml`
- `main.tex`
- `content/`
- `assets/`
- project-owned `config/`
- project-owned tests and documentation

`build/` is generated output. It is never a canonical manuscript source.

## Generated structure

```text
<project>/
├── book.yml
├── main.tex
├── README.md
├── SECURITY.md
├── .gitignore
├── content/            # profile-appropriate synthetic starter sources
├── assets/
├── config/             # title-local and semantic configuration
├── tests/
└── build/              # generated and ignored
```

## Security defaults

- LuaLaTeX is invoked through PSE with `--no-shell-escape`.
- `build/` and recipient proofs are excluded from version control by default.
- secret-like local files (`.env`, private keys) are ignored.
- unpublished projects should live in private organization-controlled storage.
- proofs should be generated with `pse proof` when recipient traceability is required.

## Generator safety

The generator:

- accepts only installed profiles whose validated manifest declares `generator_supported: true`;
- fails closed on unknown or invalid profile identifiers;
- normalizes filesystem slugs conservatively;
- rejects Windows reserved device names;
- refuses to overwrite non-empty destination directories;
- validates generated metadata before reporting success.

## Typography status

Profile typography is a reusable presentation baseline, not a house style. Title-local visual exceptions belong in `config/pse-local.tex`; semantic and security behavior remains outside profiles.

## Framework/runtime boundary

current release freezes the first distributable runtime contract. Installed projects discover the packaged PSE runtime automatically; normal use does not require `PSE_ROOT` or manual `PYTHONPATH`. `PSE_ROOT` remains an explicit development/operations override and fails closed when invalid. Runtime health is observable through `pse doctor`.

## Profile boundary

Generated projects load the selected `pse-profile-<id>` after `pse-core`, resolve profile-declared semantic modules through generated build metadata, and then load `config/pse-local.tex` when present. `config/pse-local.tex` is the sanctioned title-local typography/layout override boundary. Generated projects must not copy or edit framework profile files.
